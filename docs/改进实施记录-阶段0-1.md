## 二、阶段 1：修复内容

### 1. 资格性三态重写

文件：`api/review/qualification.py`

**修复前问题**
- 否定信号是 ±24 字窗口，且包含单字“无”；
- “无重大违法记录”“无需提供”等合规/不适用语句会把相邻“已提供”材料判成 `insufficient`；
- “未提供营业执照”被判 `insufficient`，缺失/效力不足混淆。

**修复后规则**
- 否定信号按**句界**（`。；;\n`）取，不跨句；
- 去掉单字“无”通用否定，只匹配 `无{材料名}` / `没有{材料名}`；
- `未提供/未附/未提交/未加盖/缺失/没有` → `missing`；
- `过期/失效/无效/不满足/不具备/不符合` → `insufficient`；
- `无需提供/不需提供/不要求提供/免于提供` → 仍计 `missing`，但 `applicable=false`，note 说明“不适用，需按招标文件确认”；
- R07 的“无重大违法记录/无行贿犯罪记录/无违法记录” → `provided`（合规声明，不是效力不足）。

**效果**
- bid-001：**4 已提供 / 0 效力不足 / 6 缺失**，不变；
- 合规否定式用例：`insufficient = 0`，R06/R07/R08/R10 均为 `provided`；
- “未提供营业执照/财务报告”：`missing`，不再 `insufficient`；
- “营业执照已过期”：仍 `insufficient`；
- “无需提供社保/中小企业声明函”：`missing` + `applicable=false`。

### 2. 风险去重

文件：`api/rules.py`

- `scan_doc` 在返回前按 `rule_id` 去重，同一份文档同一规则只保留第一条证据；
- risk-015 的 R35 从 2 条变 1 条，`risk_total` 不再虚高；
- MCP `scan_risks` 与 API 评审共用同一口径。

### 3. 报告九章编号

文件：`api/report/docx_export.py`、`api/report/pdf_export.py`

- 封面后增加“一、封面与文档信息”；
- 后续“二、…”到“九、免责声明”编号连续；
- docx/pdf 均验证包含“一、”和“九、”。

### 4. 文档列表一致性

文件：`api/store.py`、`web/app.js`

- `store.list_docs` 过滤非法 `doc_id`（历史 `eval` 不再出现在下拉/列表）；
- 前端 `/api/documents` 显式 `limit=1000`，避免 >200 文档时旧记录被报告中心误判“文档不存在”；
- `/api/doc/eval` 仍返回 400（非法 ID 的兜底），但不再从列表进入 UI。

### 5. 测试

新增/修改：
- `tests/test_review.py`：4 个资格性语义用例 + 文档列表非法 ID 过滤；
- `tests/test_risks.py`：R35 单文档不重复；
- `tests/test_report.py`：docx/pdf 必须含“一、封面与文档信息”“九、免责声明”。
