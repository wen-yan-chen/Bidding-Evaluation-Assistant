## 一、一句话结论

D5 把"规则库能扫"升级为"**能按一份细则给出分项得分、扣分理由与依据**"：

## 五、六个设计决策

| # | 决策 | 理由 | 代价 |
| :-: | --- | --- | --- |
| 1 | **细则放 YAML，一项一档** | 换项目=换文件，不改代码；评审可以现场改权重看效果 | 细则写错会直接算错，所以加了 `digest` 与单测 |
| 2 | **算分不用模型** | 验收要"±5 分内 ≥85%"与"3 次一致"，只有确定性代码能保证 | 模型只在 D7 负责把 `reason` 写成报告语言 |
| 3 | **每项都带 evidence（page/quote）** | 扣分必须能指回原文，否则专家不认 | 需要在算分时保存字段偏移（已由 D2 的字段模型提供） |
| 4 | **价格分用"报价/最高限价比值"分档** | 单个投标人时无法算"基准价"，比值法可独立复算 | 多投标人横向比价（基准价法）放 D6/D9 扩展 |
| 5 | **资格性三态，而不是二态** | "写了但写的是无效/未提供"与"完全没写"性质不同 | 需要上下文否定词判定（已实现简单窗口） |
| 6 | **评审结果落盘 + 双指纹** | 报告要能回答"用哪套细则、哪个规则版本算的" | 每次评审多写一个 JSON（几十 KB） |

## 六、数据结构契约（D6/D7 沿用）

```json
{
  "review_id": "rv-20261115-173019-9227ee",
  "doc_id": "20261115-9b9c80d2",
  "profile": { "id": "profile-a", "name": "综合评分法（价格 40 / 技术 40 / 商务 20）",
                "digest": "fd898ab727cf8c12", "item_count": 9 },
  "rule_digest": "a3c00ef30b02aabb",
  "qualification": { "items": [ { "rule_id": "R01", "state": "provided",
                    "page": 1, "quote": "营业执照", "legal_basis": "…" } ],
                     "counts": { "provided": 4, "insufficient": 0, "missing": 6 } },
  "scoring": { "items": [ { "item_id": "P1", "score": 40.0, "full_score": 40.0,
                 "reason": "报价低于最高限价的 90%…", "tier": "1:ratio<=0.9",
                 "evidence": { "page": 1, "quote": "投标报价：人民币 1,286,000.00 元" } } ],
               "total": 68.0, "total_full": 100.0,
               "deductions": [ { "item_id": "T1", "lost": 10.0, "reason": "未见技术方案章节…" } ] },
  "risks": [ { "rule_id": "R18", "level": "高", "page": 1, "quote": "投标保证金" } ],
  "summary": { "total_score": 68.0, "qualification_missing": 6, "risk_high": 3,
               "conclusion": "资格性材料缺失 6 项；高风险条款 3 条；当前细则得分 68.0/100.0。…" },
  "disclaimer": "AI 辅助评审结果，最终以评标委员会评审结论为准"
}
```

两条约定：

1. 报告（D7）**只能读这份 JSON**，不得自己再算一遍——否则"报告数值 = 页面数值"会被打破；
2. `profile.digest` 与 `rule_digest` 必须打印在报告页脚，用于回溯"当时用的哪套口径"。

## 七、给 D6 的输入（风险扫描与误报治理）

D5 的扫描结果已经暴露出**三类误报**，这是 D6 的重点素材（真实、可复现）：

| 误报 | 命中原文 | 为什么错 | D6 处理 |
| --- | --- | --- | --- |
| R18 投标保证金未按要求提交 | "我方已按招标文件要求提交投标保证金" | 合规定式里"已提交"被当成问题 | 在 `scan_doc` 里加 `compliant` 过滤：条款命中合规定式则跳过；并把该句写入 R18 的 `compliant` |
| R17 投标有效期不足 | "本投标文件有效期为自投标截止之日起 90 个日历日" | 只命中关键词，没有比较天数 | 改为"抽取天数 + 与要求比较"，归入 `detect=price` 同类计算规则 |
| R37 大写与小写不一致 | "…（大写：壹佰贰拾捌万陆仟元整）" | 有"大写"但金额一致 | 实现大小写金额解析比对，不一致才报 |

D6 建议顺序：① 先加 `compliant` 过滤（一次性消掉最明显的误报）→ ② 把 R12/R13/R17/R37 等改为计算型规则 →
③ 造 10 份"植入风险"样本（缺失资质、报价异常、围标特征）算检出率与误报率 → ④ 报告里给 `dev/holdout` 分档。
