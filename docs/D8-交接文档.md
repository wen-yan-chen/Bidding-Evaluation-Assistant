## 三、页面结构与交互

### 3.1 三大视图（hash 路由：`#review` / `#reports` / `#status`）

```text

#review 评审看板
  ├─ 工作台三卡：① 选择文件（已解析文档下拉 + 上传） ② 选择评分细则（profile-a/b）

  ├─ 服务自检（6 项，含免责声明逐字比对）
```

### 3.2 评审流程

1. **文件**：可从 `/api/documents` 选已解析文档，也可上传新文件。上传走 `POST /api/upload`，
   `XMLHttpRequest` 显示上传百分比与服务端解析计时；扫描件提示 13–16 秒，180 秒超时给可读错误。
2. **细则**：`GET /api/scoring/profiles` 渲染两张卡（名称、权重、最高限价/工期要求、分值总数、指纹）。
   切换只改选择，不自动重评；提示「当前结果来自 profile-a」。
3. **评审**：`POST /api/review {doc_id, profile_id}`；结果落盘后渲染。加载中按钮禁用、计时，30 秒超时提示。
4. **换细则**：切 `profile-b` 后按钮变为「用 profile-b 重新评审」；重评后：
   - 总分卡「细则对比」显示 `−6.0` 与 `profile-a 68.0 → profile-b 62.0`；
   - 分项表每行显示「较 profile-a：40.0 → 30.0 分」与 `−10.0` 徽标；
   - 若页面刷新后内存历史为空，会用 `/api/review` 列表找同文档、不同细则的上一份结果并拉详情做对比。
5. **定位**：表格「定位」与右栏证据项共用 `focusEvidence(key)`；根据 `char_start/char_end` 计算页内偏移，
   重绘该页文本并插入 `<mark class="hit">`；无偏移时回退 `quote.indexOf`；页码估算页在页头标「估算」，
   OCR 页标「OCR」；片段跨页时提示「定位起始页」。
6. **导出**：结果页与报告中心都能导出；下载走 `GET /api/report/{id}?format=docx|pdf`，
   成功后更新行内文件大小；失败按 404/400/超时给出可读提示。

### 3.3 报告中心

- 列表来自 `GET /api/review`（按时间倒序）；默认显示最近 20 份。
- 每行 `/meta` 拉取：总分/满分、资格性计数、风险数、双指纹、docx/pdf 是否存在与大小。
- **避免首页 404**：仅当报告中心可见时才请求 `/meta`；对文档已不存在的评审不打 `/meta`，
  直接显示「报告不可用：评审对应的文档已不存在」。这样干净打开首页不会产生 4xx。
- 下载按钮真实下载；同一 `review_id` 重复导出返回同一文件（后端幂等）。
- 「查看评审」会拉 `GET /api/review/{id}`，切回评审看板并渲染结果，便于从报告回溯分项。

## 六、关键实现细节（给后续维护）

### 6.1 双栏定位为什么可靠

- 解析层已保证 `full_text[char_start:char_end] == quote`；前端直接用 `char_start` 找页（`start <= offset < end`），
  再算页内偏移，不靠字符串猜。
- `resolveSpan(item)` 的优先级：`char_start/char_end` → `full_text.indexOf(quote)` → 当前页 `indexOf(quote)` → 只跳页不高亮。
- 重绘只影响目标页的 `.page-text`（用 `document.createTextNode` 与 `<mark>` 构造，不用 `innerHTML`），
  避免 XSS 和整页重排；清除高亮时把 `<mark>` 还原成文本节点并 `normalize()`。

### 6.2 报告中心为什么先判断文档存在

`/api/report/{id}/meta` 在文档丢失时返回 404。若首页加载时对全部评审都打 `/meta`，控制台会出现 404。
D8 的处理：
1. 只在报告中心可见时拉 `/meta`；
2. 先对照 `/api/documents` 的 doc_id；文档不存在直接显示「报告不可用」，不发请求；
3. 结果按 `review_id` 缓存，`/meta` 失败也缓存失败，避免重复请求；
4. 下载成功后同步更新缓存与行内大小，docx/pdf 互不覆盖（先更新 `state.reportMeta` 再 `fillReportMeta`）。

### 6.3 换细则对比为什么刷新后仍可用

运行时内存 `state.reviewsByDoc` 保存本次会话的评审历史；页面刷新后为空，则在收到新结果时从
`GET /api/review` 列表里找同 `doc_id`、不同 `profile` 的上一份评审，再拉 `GET /api/review/{id}` 详情做对比。
这样即使用户先看 profile-a、刷新页面、再切 profile-b，仍能看到差值。

### 6.4 上传与 OCR 等待

- `XMLHttpRequest` 有 `upload.onprogress` 与服务端响应两个阶段；进度条先到 100%，随后文案变
  「上传完成，服务端正在解析（扫描件 OCR 约 13–16 秒）」，并持续显示已用时间。
- 180 秒超时、网络错误、413/415 都转成可读中文；不会出现「点了没反应」。
