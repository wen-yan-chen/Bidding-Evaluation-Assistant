## 五、报告导出（已完成）

### 5.1 架构

```text
data/reviews/{review_id}.json      ← 评审结果（唯一数据源，不重新算分）
        │ api.report.builder.build(review, doc)
        ▼
九章结构化数据（meta / basis / project / qualification / scoring / risks / contract / conclusion）
        │                         │
        ▼                         ▼
api.report.docx_export      api.report.pdf_export（reportlab + 内置 CID 中文字体）
        │                         │
        └────── data/reports/{review_id}.{docx,pdf} ──────┘
                    │
        POST /api/report ｜ GET /api/report/{id} ｜ MCP export_report
```

### 5.2 九章结构

| 章 | 内容 | 关键约束 |
| --- | --- | --- |
| 一 | 封面与文档信息 | 评审编号、生成时间、页数、解析状态与降级说明 |
| 二 | 评审依据与口径 | **细则指纹 + 规则指纹**，报告可回溯"用哪套口径算的" |
| 三 | 项目与投标人信息 | 6 字段逐条带页码与原文片段 |
| 四 | 资格性核验 | 三态汇总 + 逐项依据 |
| 五 | 分项评分 | 得分/满分/理由/溯源 + 扣分汇总 |
| 六 | 风险清单 | 等级、页码、原文、依据、说明；**未命中时明确写"不等于无风险"并举出人工核对规则** |
| 七 | 合同摘要 | 六要素（标的/金额/工期/付款/违约/争议解决），抽不到写"未约定" |
| 八 | 结论与建议 | 结论 + 建议复核事项（由缺失项与扣分项自动汇总） |
| 九 | 免责声明 | 页脚同时常驻免责声明与页码 |

### 5.4 设计取舍

| 决策 | 理由 | 代价 |
| --- | --- | --- |
| PDF 用 reportlab + 内置 CID 中文字体 | 不往镜像里塞 LibreOffice（省 400–600 MB、不用连 Debian 源） | 版式自由度不如 Word，字体依赖阅读器替换中文字形 |
| 报告只读评审 JSON | 保证"报告数值 = 页面数值" | builder 不能顺手补算，缺字段只能写"未约定" |
| 报告落盘 + 幂等 | 同一评审重复导出返回同一文件 | 数据变了要删旧报告（当前未做自动失效） |
| 报告带双指纹 | 评审可核对"这份报告用的规则/细则版本" | 规则库变更后旧报告指纹会与新版不同（这是特性，不是 bug） |
