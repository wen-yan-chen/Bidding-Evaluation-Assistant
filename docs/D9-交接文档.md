## 四、`scan_risks` 口径修正（18 → 23）

旧实现：

```python
scanned_rules = len([r for r in selected if r.detect == "pattern"])  # 18
```

问题：漏掉 5 条已实现的计算型规则（R12/R13/R17/R31/R37），
平台输出「扫描 18 条」，且 18 + 10 + 7 = 35，对不上 40。

修复后：

```text
scanned_rules          = 23   （18 pattern + 5 price）
scanned_pattern_rules  = 18
scanned_price_rules    = 5
manual_rule_ids        = 10
unimplemented_rule_ids = 7
scan_notes             = 3 条
```

直接调用验证 `23 18 5 0`；`tests/test_rules.py` 锁定 23 + 10 + 7 = 40；pytest 49 passed。

## 六、设计取舍

| 决策 | 理由 | 代价 |
| --- | --- | --- |
| Skill 用唯一名 `bid-risk-selfcheck` | 平台已有 32 题同名技能，覆盖会破坏他人项目 | `agent.json` 需要改一次名并重新导入/发布 |
| `scanned_rules` 改为 23 | 与「实际执行的自动规则」一致，避免 18+10+7≠40 | 旧调用方若硬编码 18 需同步（当前只有本项目） |
| 平台输出保留 `manual_rule_ids` / `unimplemented_rule_ids` / `scan_notes` | 让模型能说清边界，不用猜 | 返回体稍大 |
| 专家评分不造数 | 评审最忌「自己造专家分」 | 第 2 条验收只能标遗留，需要 D10 补数据 |
| 状态页读 `/api/health` 显示 Skill | 页面与真实能力一致 | 多依赖一个接口字段 |
