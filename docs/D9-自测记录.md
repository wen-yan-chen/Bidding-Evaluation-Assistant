## 2. `scan_risks` 口径修正（18 → 23）

### 2.1 问题

旧实现：

```python
scanned_rules = len([r for r in selected if r.detect == "pattern"])   # 18
```

只统计关键词规则，漏掉 5 条已实现的计算型规则（R12/R13/R17/R31/R37），
所以平台输出会说「扫描 18 条」，且 18 + 10 + 7 = 35，对不上 40。

### 2.2 修复

`mcps/bid_review_mcp.py`：

```python
pattern_rules = [r for r in selected if r.detect == "pattern"]
price_rules = [r for r in selected if r.detect == "price" and r.id in checks_api.CHECKS]
unimplemented = [r.id for r in selected if r.detect == "price" and r.id not in checks_api.CHECKS]
manual_ids = [r.id for r in selected if r.detect == "manual"]
```

返回体新增：

```text
scanned_rules             = 23
scanned_pattern_rules     = 18
scanned_price_rules       = 5
manual_rule_ids           = 10 条
unimplemented_rule_ids    = 7 条
scan_notes                = 3 条（manual / 未实现 / 未载明限价）
```

### 3.6 AI 双盲参考评分（非人类专家）

真实人类专家双盲无法获得，补做 AI 代理：

- 盲评包：15 份样本（12 文本层 + 3 扫描件），只含原文/字段/页数 + `profile-a` 细则，不含引擎分；
- AI-A / AI-B（专业裁量）：15/15 彼此完全同分，但与引擎 **0/15 在 ±5 内**，平均绝对偏差 **8.27**、最大 **9.0**；
- AI-C（严格按细则）：**15/15 在 ±5 内**，平均/最大偏差 **0.0**，但这只是规则实现一致性；
- 差异根因：T2 引擎命中「实施计划」给 10、A/B 认为只是通用承诺给 5；B2 引擎给 6、A/B 只给 3；
  B3 引擎对「售后服务网络」套话给 6、A/B 给 0；属于细则 presence 档过粗，不是算错。

结论：AI 分只作代理，**不写成人类专家**；严格细则可作 15/15 的规则一致性证据，
专业裁量 0/15 作为 D10 细则校准输入。详见 `docs/TEST_REPORT.md` §4.3。
