# 资格性人工标注材料（R01–R10，25 份）

> 目标：把 25 份样本 × R01–R10 = **250 条**资格性三态标注补齐，用于
> `tools/eval_qualification.py` 计算“资质核验与人工核验一致率”。
>
> **标注员是“人工标注员”，不是评标专家；标注只判断文本写没写/是否无效，不判断证件真伪。**

## 一、文件结构

```text
02-资格性标注/
├── 标注员包/                 # 发给 2 位标注员
│   ├── 01-标注说明.md
│   ├── 02-R01-R10规则卡.md
│   ├── 03-标注表_A.xlsx      # 250 行，A 独立填
│   ├── 03-标注表_B.xlsx      # 250 行，B 独立填
│   ├── 04-样本清单.csv
│   └── 匿名样本/S01–S25
├── 组织者用/                 # 不要发给标注员
│   ├── 样本映射.csv
│   ├── 03-标注表_终稿.xlsx
│   ├── 05-一致性统计.py
│   ├── 06-转正式标签.py
│   └── make_annotation_workbooks.py
└── qualification_labels_25.json
```

## 二、怎么做（2 人独立 + 第三人裁决）

1. 找 **2 位标注员**（最好不是写算法的人；工程管理/造价/土木背景更好，没有也可以，但登记为“人工标注员”）；
2. 把 `标注员包/` 分别发给 A、B；两人**各自独立**填 250 行，约 2–3 小时；
3. 两人**不要互相讨论、不要看引擎结果、不要看对方表**；
4. 收齐后，把 A/B 表放回 `标注员包/`，运行：
   ```powershell
   python docs\评审功能测评数据\02-资格性标注\组织者用\05-一致性统计.py
   ```
   得到 `一致性报告.md` + `分歧清单.csv`；
5. 第三个人（或你）逐条看原文裁决分歧，把终稿填到 `组织者用/03-标注表_终稿.xlsx`；
6. 运行：
   ```powershell
   python docs\评审功能测评数据\02-资格性标注\组织者用\06-转正式标签.py
   ```
   生成 `qualification_labels_25.json`；
7. 备份 `data/samples/qualification_labels.json`，用新文件替换，再运行：
   ```powershell
   python tools\eval_qualification.py --strict
   ```

## 三、标注规则（摘要）

- **已提供**：原文出现材料/章节/声明，且同句无否定；
- **缺失**：全文没有；或同句写“未提供/未附/无××”；或“无需提供”（备注不适用）；
- **效力不足**：材料出现，但同句写“过期/失效/无效/不满足/不具备/不符合”；
- **无法判断**：扫描模糊/页面缺失/语义不明，备注写原因，终稿可排除；
- **“无重大违法记录”是合规声明，R07 填“已提供”**；
- **“未提供营业执照”填“缺失”，不是“效力不足”**；
- 不要用算法结果反填；不要因为“项目应该有”就填已提供。

## 四、时间与样本

- 全部 25 份约 2–3 小时/人；可以分 2–3 次做；
- 其中 S21–S25 是扫描件，可放大看；看不清就“无法判断”；
- 至少覆盖 10–15 份异常/边界（缺字段、缺工期、缺报价、缺资格材料、扫描件），
  本包 25 份已包含这些类型，不用另挑。

## 五、产出怎么用

- `05-一致性统计.py` 的一致率/Kappa 是**两位人工标注员之间**的一致性，不是与引擎的一致率；
- `06-转正式标签.py` 生成的是人工终稿；`eval_qualification.py` 会拿它和引擎比；
- 报告写“人工标注员 A/B（非专家），第三人裁决”，不要写“专家标注”；
- 如果最终只有 10–15 份标注，也可以跑，但覆盖率会显示 10–15/25，不能宣称全量 25 份。
