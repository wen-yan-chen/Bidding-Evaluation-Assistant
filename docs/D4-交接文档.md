## 五、六个设计决策

| # | 决策 | 理由 | 代价 |
| :-: | --- | --- | --- |
| 1 | **规则只放 YAML，代码只做加载与匹配** | 改依据/改阈值不用发版；评审可以直接看 YAML 抽查 | 规则写错会直接生效，所以加了 `validate_rules.py` 门禁 |
| 2 | **扫描用字面量匹配，不用模型** | 同一输入永远同一结果；命中位置天然可溯源（`str.find` 给的偏移） | 只能发现"写了什么"，发现不了"没写什么"（缺项类走 `manual`，D5 资格性核验） |
| 3 | **依据三态在代码层落地**（`Rule.legal_basis`） | 提示词管不住模型编造条号，代码能：pending 永远输出「未检索到权威依据」 | verified 只有 21 条，其余如实标注 |
| 4 | **知识库从 YAML 自动导出 + 指纹锁一致** | 手写两处必然漂移；漂移后"知识库说的"和"扫描输出"会互相打脸 | 每次改规则要重跑 `export_kb.py` 并重导知识库 |
| 5 | **MCP 工具按 `doc_id` 取数据**（不在工具里重复解析） | 解析只做一次，工具之间看到的是同一份事实；报告与页面同源 | 必须先 `/api/upload` 再调工具（文档已写明 hint） |
| 6 | **内网关闭 MCP 的 DNS rebinding 防护** | 容器内 Host 是 `mcp:8765`，新版 MCP 默认校验 Host 会回 421 | 暴露公网前必须改回白名单（代码注释已标） |

**三个踩坑（都已写进代码注释/文档）**：

1. MCP 服务容器里 Host 头是 `mcp:8765`，新版 SDK 的 DNS rebinding 防护直接返回 **421 Misdirected Request** →
   `TransportSecuritySettings(enable_dns_rebinding_protection=False)`；
2. Python 字符串里混用中文引号（`"命中即"疑似""`）会触发语法错误 → 统一用「」；
3. `validate_rules.py` 的书名号正则原来写成 `》.+?第X条`，导致 `》第十五条` 匹配不上 → 改为 `》\s*第X条`。

## 七、给 D5 的输入（评审逻辑）

1. **资格性核验**：`detect=manual` 的 9 条资质规则不能靠关键词判定，需按"已提供 / 缺失 / 效力不足"三态处理，
   输入是 `Doc.fields + clauses`，输出 `{item, state, page, quote}`；
2. **评分细则 YAML**：`data/scoring/*.yaml`，字段 `item / weight / tiers[{range, score, reason, basis}]`，
   算分用确定性代码，模型只写"扣分理由"的自然语言；
3. **换细则演示**：`profile_id` 作为参数贯穿 `/api/review` 与报告，报告页要打印"本次所用细则版本 + 指纹"（与规则库指纹同一套做法）；
4. **MCP 扩展**：D5 增加 `check_qualification` 与 `score_item` 两个工具，签名与 D4 三个工具保持一致（入参只有 id 与配置）。
