# knowledge/ — 知识库资产

与 `data/rules/rules.yaml` **同源自动导出**，避免"规则库一套、知识库另一套"：

| 文件 / 目录 | 内容 | 用途 |
| --- | --- | --- |
| `rules-full.md` | 40 条规则全文（判定条件 / 命中特征 / 合规定式 / 依据状态 / 法规依据） | 单文件上传平台 |
| `rules/R01.md … R40.md` | 同一内容按规则拆成 40 个文件（`tools/split_kb.py` 生成） | 平台按大小切分时，保证"一块一条规则" |
| `rules/index.json` | 拆分清单（规则号 / 标题 / 字符数） | 核对是否 40 份齐全 |
| `manifest.json` | 指纹 / 条数 / 生成时间 / 源文件 | `validate_rules.py` 与报告引用 |

检索配置：`hybrid` + `top_k=3`，embedding 用本地 `bge-m3`（1024 维）。

## 切分这件事踩过的坑（D6 实测）

把 22 KB 的单文件 `rules-full.md` 传进平台后，ES 里只有 **8 个分片**（约 2.8 KB/块）——
平台按**大小**切，不按 `## Rxx` 标题切，于是多条规则混在一块、单条规则被切碎。
检索虽然还能命中（问 R12 能答对），但精度不稳，评审抽查 20 条时容易串号。

两种解法：

1. **推荐**：上传 `rules/R01.md … R40.md` 这 40 个小文件（一文件一规则，至少一分片）；
2. 或在平台上传/分片设置里把 chunk size 调到 300–600 字、overlap 50 左右。

## 导入后必做验证（30 秒）

在对话里问「R12 的判定条件是什么？依据是哪个条款？」：

- 正常：返回 R12 判定条件 + `verified` 依据（实施条例第五十一条第五项）；
- 全答"未检索到权威依据"：`index_names` 没换或索引未完成；
- 返回旧内容（如"报价计算（D6 实现）"）：知识库没重新上传，与代码口径不一致。
